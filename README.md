# WoW Forever — кулинарный дашборд (EU PvP Орда)

Локальный веб-дашборд на Python: тянет цены из TSM Public Data, считает экономику крафта
и показывает таблицу блюд с ингредиентами, прибылью и списками покупок для Auctionator.

## Запуск

1. Двойной клик по **`start_dashboard.bat`** — сервер поднимется и сам откроет браузер
   на `http://127.0.0.1:8080`.
2. Или вручную:

```
python dashboard_server.py            # откроет браузер сам
python dashboard_server.py --port 8080 --no-browser
```

Пока окно сервера открыто, цены TSM обновляются автоматически каждые 3 часа.
Остановка — `Ctrl+C` или закрыть окно.

## Что на экране

| Колонка | Что означает |
|---|---|
| Себестоимость | сумма по реагентам, для каждого берётся минимум из цены вендора и аукциона (MinBuyout) |
| Вендор | сколько вендор платит за крафт (все порции сразу) |
| Прибыль вендору | выручка вендора − себестоимость, **зелёная строка = гарантированный плюс** |
| Аукцион | TSM MinBuyout за крафт |
| Прибыль на аукционе | выручка − 5% комиссии − себестоимость |
| Выкуп / ликвидность | если TSM отдаёт `saleRate`/`soldPerDay` — реальные цифры; иначе оценка по спреду `minBuyout/marketValue` и тренду `recent/historical` |
| Вердикт | «Вендору» (безопасно), «На аукцион» (заметно выгоднее и рынок живой), «Не крафтить», «Проверить» (нет цены реагента) |

Клик по строке (или по стрелке ▶) раскрывает спойлер с ингредиентами: количество,
цена за штуку, источник цены, сумма и сортировка по сумме / цене за штуку / количеству / имени.

## Auctionator

* Кнопка **⇩** у блюда — список покупок его реагентов.
* Кнопка **⇩** у ингредиента — закупка одного реагента.
* Кнопка **«Импорт всех профитных ингредиентов (Auctionator)»** — реагенты всех блюд
  с положительной прибылью вендору, без дублей, количество суммируется.

В модалке можно выбрать формат (по умолчанию `Название;;макс_цена_в_меди;количество`),
число крафтов и язык названий (ruRU / enUS). Список копируется в буфер автоматически;
в игре: **Auctionator → Покупки (Shopping) → Импорт → Ctrl+V → Импорт**.

Максимальная цена закупки — цена реагента +20% запаса (настраивается `PRICE_NAP_FACTOR`
в `dashboard_server.py`).

## Настройки

* **`vendor_prices.json`** — цены покупки реагентов у вендора в меди. Файл перечитывается
  при каждом обновлении данных: правьте цены под свой сервер, перезапуск не нужен.
  Если реагента нет ни в этом файле, ни на аукционе, блюдо получает вердикт «Проверить».
* **`dashboard_server.py`** — `AH_COMMISSION` (5%), `REFRESH_HOURS` (3), `TSM_REALM_CANDIDATES`.

## API

| Эндпоинт | Назначение |
|---|---|
| `GET /api/data` | все блюда с расчётами |
| `GET /api/update` / `POST /api/update` | принудительное обновление TSM |
| `GET /api/status` | состояние фонового обновления |
| `GET /api/auctionator?scope=all\|dish\|reagent&id=&fmt=&qty=&lang=` | строка импорта |
| `GET /api/export.csv` | выгрузка таблицы в CSV |

## Файлы

* `dashboard_server.py` — сервер, расчёты, TSM, фон-обновление
* `index.html` — интерфейс (тёмная тема, без внешних зависимостей)
* `vendor_prices.json` — цены вендора
* `recipes_cache.json` — рецепты (из парсера)
* `tsm_prices_cache.json` — кэш последней загрузки TSM (создаётся автоматически)
* `start_dashboard.bat` — запуск в один клик

## Почему нет «скорости продаж» в цифрах

TSM Public Data для `forever/eu/realm/pvp-horde` отдаёт только
`itemId, name, marketValue, minBuyout, recent, historical, updatedAt` — без
`saleRate`, `soldPerDay`, `quantity` и `numAuctions`. Поэтому ликвидность считается
по прокси (спред минимального лота к рыночной цене + тренд recent/historical),
а в интерфейсе это явно подписано. Когда TSM добавит поля, дашборд начнёт показывать
их автоматически — код читает любые из этих колонок, если они появятся.
